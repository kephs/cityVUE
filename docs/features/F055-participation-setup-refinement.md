## Interaction and wording contract

Page: **Participation Setup**. Introduction: “Configure optional service-participation information for new requests.” Section 1: **Service Participation**, “Ask requesters for an optional Participation Area.” The native checkbox uses `role="switch"`, accessible name “Service Participation collection”, checked state and visible **On/Off** text. Space toggles a local draft. It never auto-saves. Read-only users see plain On/Off and no fake switch or mutation controls.

The loaded collection state explains requester behavior. Unsaved changes explicitly identify the currently persisted On/Off value. **Save changes** is disabled without a valid dirty draft; **Cancel change** restores the loaded value and switch focus without writing. Turning off requires the native dialog “Turn off Service Participation?” and explains that existing responses/historical analytics are kept. Cancel receives initial focus; Escape/cancel restores focus. Confirm calls only the accepted F053 API with that collection's expectedRevision. With zero active areas, enabling is unavailable with “Add or reactivate at least one Participation Area before turning this on.” Server validation remains authoritative. A 409 requires explicit refresh; no automatic retry.

Section 2: **Participation Areas**, actual active/inactive configuration counts, “Choose the areas requesters can select.” **+ Add area** is the primary action. Compact rows show name, Active/Inactive, actual **Order N**, Rename, Change order and Activate/Deactivate when authorized. Technical revision disclosures/raw IDs are removed from normal presentation. Numeric order uses the **Display order** field and existing integer validation. Save changes only that area and uses its expectedRevision. Names retain trimmed case-insensitive Organization-scoped active/inactive uniqueness; retired names remain reserved.

Deactivation explains reversibility and retained history. For the final active area with collection On: “Turn off Service Participation first if you want to deactivate the last active area.” Areas stay visible when collection is Off, with “Areas are kept for future use and historical records.” An invalid On/zero-active state warns without repairing data. Successful area writes refresh the server-sorted area page and focus the affected area, or the section status if the area is outside the current page. Collection success focuses the switch. Feedback stays near its section and clears on navigation/full refresh.

Each editor's draft is independent. An area save/area-page refresh does not overwrite an unsaved collection toggle; collection Save does not discard an open area editor. Full Refresh asks before discarding either edit. Area-specific refresh/pagination asks before discarding an area edit and preserves the collection draft. In-flight operations disable destructive refresh of their editors. Denied writes clear/recheck authoritative Admin read access; failed scoped reloads use the same safe parent reload. Requests abort on unmount and late responses are ignored. Navigation reloads authoritative configuration, preventing cached pre-save values from reappearing on Overview.
