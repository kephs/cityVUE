## Design and boundaries

Request UUID and human reference confer no requester authorization. A server-generated 32-byte cryptographically random base64url bearer credential authorizes only an explicit requester projection. SHA-256 digests are stored; raw credentials are returned only on successful issuance/rotation. This is high-entropy token hashing, not password hashing. Possession does not verify human identity.

Management requires `service_request.view`, `service_request.tracking.manage`, trusted active Organization/staff identity and current parent scope. Only persisted PUBLIC requests are eligible. No default grants or historical credentials are created. F036 registration/bundle changes require explicit provisioning after a negative baseline.

The separate credential table retains revoked records. A partial unique index permits one active credential per request. Parent-row serialization and management-version checks prevent simultaneous or stale operations from silently replacing another operator's link. Required metadata-only audit and state mutation commit atomically. Request revision, updatedAt, Activity, Notes, Communication, Contact, assignment and watchers remain unchanged. Automatic expiry is deferred; rotation and revocation are explicit.

Tracking links use `/track#<credential>`. Bootstrap consumes and removes the fragment before routing; the API receives the secret in `X-Requester-Tracking`, never a path/query. The credential remains in private page memory only for retrieval/retry and is discarded on leaving. Refreshing the scrubbed URL requires reopening the original link. Staff management clears one-time links on dialog close/request or access changes. Copying requires explicit user action. No credential enters persistent browser storage, analytics or titles.

The requester view is separate from the staff navigation shell. Its explicit projection contains reference, Issue name/safe icon, normalized status, submitted timestamp, original description and service location. No UUID, revision, routing, Department/Division identities, staff identity, Contact, Notes, Activity, Communication, audit or capability fields are returned. Requester Communication and requester history remain deferred.

Existing global API throttling and safe route-template logging are retained. Tracking/management responses require no-store, no-referrer and noindex protections, including failures. Browser fragment scrubbing cannot erase prior clipboard, browser synchronization, screenshots, extensions or forwarded-link copies. Local assets and early restrictive referrer policy minimize leakage; deployment proxy/header logging must also exclude the credential header. Database disclosure reveals digests and protected request data but does not directly yield usable 256-bit links. Production distributed throttling, HTTPS deployment and load testing remain separate requirements.
